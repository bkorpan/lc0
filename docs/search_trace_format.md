# Search Trace Binary Format

Search trace files record the full MCTS simulation traces from batched selfplay
games. Each trace is the sequence of moves (as NN policy indices) taken from the
root to a leaf node during a single MCTS simulation.

Generated by `--search-trace-file=<path>` when using batched selfplay
(`--batched-games=N`).

## File Layout

All integers are little-endian.

### File Header (16 bytes)

| Offset | Size | Type   | Field      | Description                         |
|--------|------|--------|------------|-------------------------------------|
| 0      | 4    | uint32 | magic      | `0x5443484D` (ASCII "MCHT")         |
| 4      | 4    | uint32 | version    | Format version (currently 1)        |
| 8      | 4    | uint32 | num_games  | Total number of games in the file   |
| 12     | 4    | uint32 | reserved   | Reserved, must be 0                 |

### Per Game

Games are stored sequentially after the file header.

#### Game Header (4 bytes)

| Offset | Size | Type  | Field      | Description                          |
|--------|------|-------|------------|--------------------------------------|
| 0      | 2    | uint16| num_plies  | Number of plies (half-moves) played  |
| 2      | 1    | int8  | result     | Game result: 1=white, -1=black, 0=draw |
| 3      | 1    | uint8 | reserved   | Reserved, must be 0                  |

#### Played Moves (2 * num_plies bytes)

Array of `uint16[num_plies]`. Each entry is the NN policy index of the move
played at that ply. Indices are in the side-to-move perspective (same encoding
as the neural network policy head).

#### Per-Ply Traces (num_plies entries)

For each ply, the search traces from the MCTS search that preceded the move
choice at that ply:

##### Ply Header (2 bytes)

| Offset | Size | Type   | Field       | Description                      |
|--------|------|--------|-------------|----------------------------------|
| 0      | 2    | uint16 | num_traces  | Number of MCTS simulations       |

`num_traces` equals the `--visits` parameter (e.g., 100 for `--visits=100`).

##### Per Trace

Each trace is a variable-length record:

| Offset | Size          | Type   | Field     | Description                    |
|--------|---------------|--------|-----------|--------------------------------|
| 0      | 1             | uint8  | trace_len | Number of moves in this trace  |
| 1      | 2 * trace_len | uint16 | moves     | NN policy indices, root→leaf   |

- The first simulation (root node expansion) has `trace_len=0`.
- `moves` are NN policy indices in side-to-move perspective at each node.
- Traces are in the order they occurred during the search (see note below).

## Notes

- **Move encoding**: All moves use `MoveToNNIndex()` with `transform=0`.
  Edge moves in lc0 are already in the side-to-move perspective, so no
  board flipping is needed.

- **Trace ordering**: Traces within a ply are ordered by simulation sequence.
  Simulations that resolve immediately (terminal nodes, NN cache hits) may
  appear slightly out of order relative to simulations that required a batched
  NN evaluation, but this reordering cannot occur within a single game's
  simulation sequence.

- **Result convention**: The `result` field uses absolute color perspective
  (1 = white won), unlike the internal node value convention which is relative
  to the parent.
